# ClawManager AI Gateway 图片能力扩展实施计划与进度报告

更新时间：2026-10-23  
范围：图片识别、图片生成与编辑、图片 Auto 路由、Agent 工具接入及配套治理。  
依据：当前本地代码、此前实施轮次的自动化验证记录及现有操作指南；不是线上验收报告。

## 一、汇报摘要

本次扩展是在已有 ClawManager AI Gateway 上增加图片能力，继续复用模型管理、用户授权、Virtual Key、限流、预算、任务取消和审计，不另建绕过治理的供应商调用通道。

目前已经实现三条主线：

1. **识图**：管理员可以配置聊天模型是否支持图片输入；Gateway 按用户权限和识图能力处理显式选模及 Auto 请求。
2. **生成与编辑**：已接入非流式 Images API，支持图片生成、图片编辑、受保护的结果保存、幂等任务和异常恢复。
3. **Agent 使用**：已完成固定版本 OpenCode 的图片工具、工作区保存及编辑链路，并新增独立的图片 Auto 路由。

**当前不是“只剩验收”**：流式图片事件、Responses 内置生图工具、其他运行时图片工具以及真实账单对账等仍有开发工作。已完成部分也需要构建镜像、更新测试 K8s，并完成真实供应商和实例端到端验收。

建议汇报口径：

> 图片能力的第一版基础链路和治理能力已经落到代码，并通过本地自动化验证。当前可以进入新版镜像部署和真实实例联调；完整计划仍需补齐流式生图、Responses 内置生图工具、其他运行时接入及账单恢复等能力，不能把代码完成等同于已上线。

### 2.1 三种能力分别配置

| 能力 | 用户侧用途 | 管理与路由含义 |
| --- | --- | --- |
| 图片识别（Vision） | 给聊天模型发送图片并提问 | 聊天模型的输入能力，不代表能生图 |
| 图片生成（Generation） | 根据文字生成图片 | 图片模型的生成能力，使用独立图片调用链 |
| 图片编辑（Edit） | 上传已有图片，按指令修改，可携带遮罩 | 图片模型的编辑能力，与生成能力分别开启 |

### 2.2 协议边界

- 识图覆盖 OpenAI Chat、Responses 和 Anthropic Messages 的相关图片输入处理；不支持的输入形式明确拒绝，不能宣称任意文件格式均支持。
- 当前原生生图、编辑入口使用 OpenAI/OpenAI-compatible Images API。
- Anthropic 会话可以通过已接入的 Agent 函数工具调用 Gateway 生图；**这不是新增 Anthropic 原生生图端点**。
- Responses 内置 `image_generation` 是另一条协议链，不等同于普通函数工具，目前仍待开发。
- 本轮不修改 OpenCode 的聊天界面，不扩展 Team 业务。

- [x] `POST /api/v1/gateway/llm/images/generations`：非流式生成。

### 4.3 授权、限流、预算和取消

- [x] 图片模型按实例所有者授权，不因 Auto 或工具调用绕过可见范围。
- [x] 检查 Virtual Key 允许的模型范围及已有请求治理条件。
- [x] 接入 Key 限流/并发、部署并发、预算预占和结算。
- [x] 严格治理实例携带任务、会话和运行时代际，遵守取消与撤权边界。
- [x] 读取图片制品时重新检查身份、所属范围、有效期和模型当前权限。

预算按管理员配置的单张价格估算，**不是供应商实际费用**。连接中断或结果未知时保守保留估算，不自动重试付费请求；已发生的供应商计算无法保证撤销或免单。

### 4.4 持久化任务、结果保存与可靠记录

- [x] 同一身份范围内，通过幂等键和请求指纹防止重复提交。
- [x] 持久化任务状态，并提供状态查询接口。
- [x] 图片加密保存，默认保留七天，过期禁止访问并后台清理。
- [x] 服务恢复后处理准备中/运行中异常任务，不重新调用供应商。
- [x] 预算按原预占记录幂等结算，避免重复结算。
- [x] 使用任务表持久化分析快照，调用记录与费用分析记录在事务内补写。
- [x] 分离预算结算状态 `settled` 与分析记录状态 `records_ready`。

恢复器不能凭空恢复未持久化的图片，也不能补回没有快照的历史漏记。未知结果不伪造实际 Token、真实费用或完成耗时。

主要代码：[任务服务](../backend/internal/services/gateway_image_job_service.go)、[制品服务](../backend/internal/services/gateway_image_artifact_service.go)、[分析记录补写](../backend/internal/services/gateway_image_analytics.go)、[迁移 074](../backend/internal/db/migrations/074_add_image_analytics_outbox.sql)。

### 4.5 图片 Auto 路由第一版

- [x] 先筛选当前用户和 Key 可用、启用、具备对应图片操作能力且估算价格有效的模型。
- [x] 排除冷却中、并发已满、半开探测占用的部署。
- [x] 优先部署优先级；同优先级结合近期图片完整请求耗时和在途负载排序。
- [x] 排序分数相同时比较估算价格，并对同价候选分散选择。
- [x] 返回实际选中模型，调用记录保留“请求 auto”和“实际部署”的区别。
- [x] 幂等请求固定原选中模型；撤权或失败后不自动切换供应商重做。

此处不使用聊天规则/Laya 分类、聊天能力档位、TTFT 或 Token 速度。跨副本实时健康与负载依赖 Redis；使用 Noop 存储不具备共享负载和并发保证。第一版也不保证最低价格或严格平均分流。

- [ ] 覆盖跨副本、重复恢复、部分失败及金额/用量一致性测试。

完成标准：能区分估算、供应商实际金额和调整流水；预算、分析记录与 TPM 恢复各自幂等，不互相冒充完成。

## 七、最终验收清单

以下全部是待在部署环境确认的事项，不因单元测试通过而自动打勾。

- [ ] 管理页面能够分别保存识图、生成、编辑配置，刷新后保持一致。
- [ ] 同一供应商下不同模型、不同 URL 下的部署能够分别授权。
- [ ] 不可见模型不出现在用户可用目录，显式调用和 Auto 均不能绕过授权。
- [ ] 图片输入在实际支持的聊天协议中保留正确结构，不被变成普通文本。
- [ ] 原生 Images API 完成生成、编辑和制品下载；错误参数不会意外产生重复任务。
- [ ] OpenAI 与 Anthropic 会话分别完成 OpenCode 图片工具闭环。
- [ ] Workspace 中可以找到保存结果、预览并下载；同名覆盖和越界写入被拒绝。
- [ ] Auto 返回的实际模型与调用记录一致，幂等重放不更换部署。
- [ ] 预算不足、并发超限、上游拒绝、超时和取消均有明确状态。
- [ ] 撤权阻止后续访问和继续调用；不承诺删除已经下载的本地副本。
- [ ] 重启后预算与分析记录可以恢复，不再次请求供应商，不重复产生记录。
- [ ] 图片过期、清理及数据库/对象存储联合备份符合预期。
- [ ] 旧实例与已有聊天业务回归通过。
- [ ] 测试报告注明镜像摘要、环境、测试范围、未覆盖项及回滚方案。

## 八、风险与有意保留的边界

1. **外部执行不能原子回滚**：供应商已开始的生成可能继续计费；不能承诺严格一次外部执行或取消即免单。
2. **禁止自动付费重做**：失败、未知结果或已固定的任务不自动切换供应商，这是防重复费用的设计边界。
3. **估算不等于真实账单**：当前单张估算价不随尺寸/质量自动变化，需管理员保守配置。
4. **能力开关不赋予模型能力**：管理员开启识图、生成或编辑，不代表供应商实际支持。
5. **图片安全不是只有提示词检查**：当前复用文本风控，图片像素内容审核尚未实现；如需该能力，应另行明确范围。
6. **本地文件不是可撤回内容**：已保存/下载的图片不随模型撤权删除；工作区写入也不是防所有外部进程竞争的操作系统级独占事务。
7. **共享基础设施是前提**：多副本验收需要共享 Redis 与对象存储；不能用每 Pod 独立本地目录替代可靠共享存储。
8. **界面与旧实例边界**：不修改 OpenCode 会话内图片 UI，不强制所有旧实例升级，不声称其自动具备新工具。
9. **可选后续优化**：供应商输出 URL 获取、Files ID 解析、尺寸/质量分桶路由、动态定价等需单独确认优先级，不列入当前已完成功能。
