# Auto 模型路由

本功能运行在 ClawManager 自有 AI Gateway 内，不依赖另起一个 LiteLLM Proxy。
只有经过该网关且请求 `model: "auto"` 的调用会使用内容路由；直接访问厂商 API、显式指定模型或模型组的请求不会按复杂度换模型（安全策略仍然生效）。

分类阶段现已提供代码级 `RoutingClassifier` 扩展接口；默认仍使用现有规则，不增加模型调用。接入契约、超时兜底和后续 Laya 适配注意事项见 [可替换路由分类器](routing-classifiers.md)。本次未增加管理端切换入口，也未部署外部分类服务。

## 配置

模型管理页新增“自动路由能力档位”，API 字段为 `quality_tier`：

| 值 | 管理员确认的能力 |
| --- | --- |
| 0 | 未分级；为兼容旧配置，按 1 档参与，记录警告 |
| 1 | 简单问答 |
| 2 | 通用任务、常规编程 |
| 3 | 架构、分布式系统、复杂任务 |
| 4 | 证明、推导等高阶推理 |

档位表示管理员对模型的能力评估，不根据模型名称、价格自动猜测，也不会开启或关闭厂商的思考模式。应根据自己的评测设置。
配置输入/输出单价、币种、实际上下文容量和单个物理部署的最大并发请求数；价格 0 按免费计算，上下文容量 0 表示未知，最大并发 0 表示供应商没有提供明确上限。
升级会通过迁移 `054_add_llm_model_quality_tier.sql` 将旧模型设为未分级，不修改其安全属性、价格或 API Key。
迁移 `056_add_gateway_deployment_routing.sql` 增加部署并发容量以及调用 TTFT、生成耗时、tokens/s 和尝试次数字段。
旧客户端更新时省略 `quality_tier` 会保留已有档位，显式传 0 才会清除评级。

### 工具调用开关

模型配置的规划表新增“支持工具调用”，单模型编辑和批量导入均可逐行设置：

- 勾选并保存：管理员确认支持工具调用，该模型不会因工具能力被 Auto 排除。
- 取消勾选并保存：带非空 `tools` 定义的 Auto 请求会排除该模型，记录 `tools_not_supported`；普通文本请求不受该开关影响。
- “未确认”表示没有手动选择且缺少可靠能力信息。模型名称规则和 `unknown` 不再被当作“不支持工具调用”，保留旧配置兼容行为。这不是对模型真实能力的验证，仍应按供应商实际支持情况确认。

手动设置通过独立的可空字段 `tools_support_override` 保存，`true`/`false` 优先于自动发现结果；旧客户端省略或传 `null` 时保留已有选择，不会清除手动设置。迁移 `058_add_llm_model_tools_override.sql` 仅新增可空列，不修改既有能力、安全标记、价格或密钥。当前没有“重置为自动检测”操作。

开关只是模型能力声明，不会为上游模型增加工具功能，也不会绕过安全模型、Key 权限、上下文容量等要求。保存后新的 Auto 请求使用新设置；显式指定模型的请求不走此筛选。刷新发现结果和取消编辑分别保留手动选择、恢复编辑前的选择。

## 选模顺序

1. 原有风险检测扫描完整会话；阻断/审批策略优先，只有动作明确为 `route_secure_model` 的规则才强制进入安全模型，`allow` 命中只记录审计。安全切换也不能越过 Key 的模型组权限。
2. 用最新用户任务的意图、领域和约束估算难度。系统提示和工具输出不计入难度；工具调用期间保持原用户任务。明确续问回看近期任务，独立新问题不继承旧难度。细则见下文。
3. 排除停用、Key 无权访问、不满足安全要求、协议不支持、币种与受管预算不符、估算输入与预留输出之和超过已配置上下文容量的部署。完整历史和工具定义计入输入估算。目前调用适配器支持 OpenAI / OpenAI-compatible / Anthropic；Google、Azure 原生协议不会成为 Auto 候选。Anthropic 不承接 `n > 1`。
4. 保留满足所需能力档位的模型。如果没有，使用当前约束下的最高可用档位，并记录 `insufficient_quality_tier_best_available` 降级警告；不会绕过安全/权限/容量限制。
5. 先在每个模型组内按部署优先级确定代表部署，组之间使用估算输入成本 + 输出成本选择最低成本。统一识别 `max_tokens`、`max_completion_tokens`（Responses 的 `max_output_tokens` 在协议入口转换）；同时提供时保留原有 `max_tokens` 优先规则。未指定则使用 4096 tokens，且实际发送同一上限；`n` 会乘入输出预占。选模、TPM 与预算预占使用同一输入估算。它们不是实际账单；结算优先采用上游 usage，缺失时才按同一输入规则及实际返回内容估算，并标记估算值。
6. 不跨币种直接比较数值。候选币种不一致时，按部署优先级、名称确定性选择，并记录 `mixed_currencies_priority_order_no_cost_comparison`。
7. 在最终模型组的物理部署之间，根据共享的实时并发、TTFT、端到端延迟、生成速度和健康状态选择首选部署；故障切换仍保留同组、相同安全属性，只使用满足能力与上下文要求的候选。已有预算、限流和流式提交后的不可重试规则继续生效。

### 部署负载与可用性（adaptive-performance-v1）

- 每次调用通过 Redis Sorted Set + Lua 原子占用并发槽，多个 ClawManager 副本看到同一份在途负载；租约带心跳和 TTL，进程异常退出后也会自动回收。
- 成功调用以 EWMA 更新 TTFT、总延迟和输出 tokens/s。路由分数预测“首 token 等待 + 预期生成耗时”，再乘以实时负载和健康惩罚；性能相近的部署使用按用户/会话稳定的两选一分流，10 分钟内保持软粘性，减少同一会话的体验抖动。
- 新部署有 5% 的受控探索机会以建立性能样本。连续 3 次可归因的网络错误、429 或 5xx 会进入 30 秒冷却；冷却后只允许一个半开探测请求，成功恢复健康状态。
- Redis 性能指标不可用时回退到管理员配置的静态部署优先级。对于已设置最大并发数（大于 0）的部署，若并发槽检查失败或未配置 Redis，则跳过该部署并尝试已有合规候选，不能绕过上限；没有可用候选时返回暂不可用。最大并发为 0 的部署仍允许静态降级。达到明确并发容量或处于冷却期时同样不会直接放行。
- 上游 HTTP 403 若明确返回 `permission_error`、`model_access_denied` 或 `model_not_allowed`，按部署权限故障处理：在尚未输出内容时切换已有合规候选，并立即进入 30 秒 Redis 冷却；在途旧请求的成功或其他失败不会提前解除冷却。冷却到期沿用单请求半开探测。流式与非流式统一处理，成功后记录实际模型；无合规候选或全部失败时保留上游错误。未知/WAF/内容策略 403 不触发这项切换，ClawManager 本地鉴权、风险阻断和 Key 模型组权限不变。Redis 不可用时仍可在当前请求切换，但不保证跨请求共享冷却。
- OpenAI-compatible 与 Anthropic 流式调用在首个文本或工具调用前最多缓冲 256 KiB 协议前导帧。上游在首个有效 token 前断流时可安全切换，向客户端提交首个有效事件后不再重试，避免重复输出。

### 复杂度判断（content-cost-v4）

本地、确定性的中英文规则判断，不额外调用模型，不增加分类模型费用。`score` 是规则等级分，不是概率或模型置信度。v4 在 v3 意图识别基础上补充口语任务、带补充内容的续问、业务约束和形式化论证；仍不靠技术名词命中次数或文本长度加分：

| 用户任务示例 | 要求档位 | 判断依据 |
| --- | --- | --- |
| “什么是分布式架构？”、“死锁是什么？” | 1 | 概念问答，不因领域名词升档 |
| “翻译：Prove the theorem…” | 1 | 翻译任务，不是要求执行材料中的证明 |
| “写一个 Python 函数排序”、写邮件、常规比较分析 | 2 | 明确的编程、撰写或分析意图 |
| “弄个小游戏”、“拟一份通知” | 2 | 口语创作动作与目标产物同时出现 |
| “设计分布式架构”、“排查并发死锁根因” | 3 | 复杂领域和实际设计/分析/排查意图同时成立 |
| “设计方案，兼顾延迟、预算、可用性” | 3 | 实际任务含至少三类不同约束 |
| “证明这个定理”、“推导方程” | 4 | 证明/推导意图；“工作证明文件”不算数学证明 |
| “从公理出发严格论证”、“论证循环不变式” | 4 | 论证动作与数学/形式化对象同时出现，普通商业论证不升到 4 档 |

- 约束按性能、资源/成本、可靠性、安全/合规、兼容性、事务一致性六类去重；重复写“性能”不累加。支持“不能丢订单”“扣款不能重复”“数据不能出境”“旧系统逐步接入”等部分业务表达。整体方案同时涉及可靠性和事务一致性时，按 3 档处理；不是任意两个约束都升档。
- 多组件故障需要至少两类不同运行症状（如连接池耗尽、队列积压），同时有排查/因果分析要求，才按 3 档处理。罗列症状、词义查询、翻译日志不因此升级。
- 规则分使用层级最大值：一般任务 0.25、复杂领域任务 0.55、多约束任务 0.65、形式推理 0.85；不会因为多个普通规则叠加而变成形式推理。档位阈值仍为 0.2、0.5、0.8。
- 代码围栏、Markdown 引用行、双引号/中文引号/行内代码中的文字按材料处理，不把其中的关键词当作命令。“解释这段代码”仍可识别为技术任务。翻译/摘要等任务中，冒号或换行后的部分视为材料；复合要求应写在材料之前，例如“总结并证明这个定理：…”。支持常见“不要证明…”的否定句，但不是完整自然语言否定解析。
- “请继续分析”“继续，把边界情况补上”“接着来，…”“换一种方法”“这个方案…”等明确续问保留当前要求与上文任务的较高难度，最多回看 8 条用户消息，遇到独立任务即停止。“继续教育”之类词组不是续问。问候、新问题、单纯总结上文不继续沿用旧的高难度。“把上面的结论总结成一句话”和“继续，总结上面的结论”按转换任务处理；若还要求编程或证明，独立计算当前新增要求的难度。无可用上文时最低按 2 档并记录 `followup_context_unresolved`。这只是单次请求内的上下文识别，不是固定会话模型粘性。
- 大写/小写/缩写不再因包含“写”字误判为写作；“写一个转换大写的函数”仍是编程任务。新增口语动作也遵守常见否定句过滤。
- 每条用于难度分析的文本最多取前 12000 和后 4000 字符；超长时记录 `difficulty_text_truncated`，中间的要求可能遗漏。实际发给模型的内容和计费/容量估算不截断。
- 结构化文本正常分析，图片/音频等非文本内容不从 URL 或元数据猜难度；最低按 2 档并记录 `non_text_content_not_classified`。这不表示已经校验模型的视觉/音频能力。
- 审计保留版本、等级、触发信号（如 `complex_task_intent`、`multiple_constraint_families`、`followup_context`）和警告，不加入原始任务文本。

仍可能误判隐含意图、特殊否定表达、引用格式不规范的材料、未覆盖语言和更早的省略上下文。规则配置化、语义分类器和线上反馈校准尚未实现。输入 token 也是估算，不代替厂商 tokenizer 或多模态容量校验。

## 如何确认生效

使用两个独立模型组，配置好实际能力档位、相同币种单价和 Key 可访问范围，并确认实例请求走平台网关且模型为 `auto`。

- 简单问题（如“你好”）：应在满足约束的模型组中选择估算成本最低者，即使两个模型都标为安全也一样。
- 复杂问题（如“设计分布式系统架构并分析权衡”）：应排除 1/2 档模型；若没有 3/4 档，允许最佳可用模型响应，但产生降级警告。
- 打开 AI 审计详情中的“自动选模记录”，展开对应请求；事件 `gateway.routing.selected` 包含难度分数、规则信号、要求/实际档位、模型组、估算成本、币种及警告，不包含原始提示词。
- 选模失败记录 `gateway.routing.rejected`，同样在该页面展示。`rejections` 按候选 ID/模型组列出权限、安全、协议、币种、上下文、档位排除原因；不会记录提示词或 API Key。没有候选返回 503，风险阻断仍返回 403，非法生成参数返回 400。
- 最终实际使用的模型以调用记录 `actual_provider_model` 为准；如果发生故障切换，还会有 `gateway.deployment.failover` 事件。路由事件记录的是初选模型。

## 预算币种与升级

受管 Gateway Key 的预算账本统一为 USD（包括 `limit=0` 但仍记账的 Key）。非 USD 模型不会进入这类请求的 Auto 或故障切换候选；显式指定非 USD 模型返回 409。不启用预算控制的其他鉴权路径仍可调用其他币种模型。本轮不进行汇率换算。

迁移 `055_gateway_budget_currency_review.sql` 会标记存在非 USD 历史费用的 Key，保留全部费用记录。被标记的 Key 在管理员核对并明确执行现有预算 API 的 `reset_usage: true` 前拒绝新预算预占（409）；仅修改周期、自然周期重置不能解除标记。该操作重置预算计数，不更改历史费用或原预算上限（请求中应保留所需的 limit/period）。应先停止该 Key 的在途请求，再核对重置。

预算用量 API 返回 `currency: USD`，`all_time_estimated_cost` 仅表示历史 USD 费用，所有币种分别放入 `costs_by_currency`。被标记时，旧计数放入 `unverified_legacy_spent` / `unverified_legacy_reserved`，不作为 USD 余额展示；`currency_review_required` 为 true。

只改代码不会更新运行中的镜像。本轮不执行实际数据库迁移或预算重置。部署时应停止旧版网关接收请求、等待在途调用完成，执行迁移并统一更新全部网关后再恢复流量，避免旧进程继续写入混币账目。随后配置模型档位并验证流式、非流式调用。
