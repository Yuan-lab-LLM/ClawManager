# Runtime 升级与休眠状态闭环

用户已批准扩展现有 CM 升级功能，后续 AgentRuntime 镜像更新必须通过该功能。保留当前54故障现场，本轮开发及隔离验证不执行业务运行池恢复。

## 设计选择

沿用现有 rollout、leader、admission、持久 checkpoint 和完成验证。选择“证明旧休眠身份→受控唤醒→现有升级→原生注册验证→CM自行休眠”路径。它复用当前启动/数据兼容规则，并通过新自动休眠操作生成新快照。拒绝直接在0副本上替换镜像后修改旧journal的做法；不另造外部升级状态机。

## 安全边界

- 普通调度 inventory 仍排除0副本；升级独立发现带自动休眠标记的候选，仅接受completed自动缩容journal、精确Deployment UID/模板/generation、原PVC身份及无剩余Pod的证明。手工scale-to-zero、旧池、无证明或已漂移池明确阻塞。
- 管理员提交 `/admin/runtime-rollouts/prepare` 创建 `rollout_wake` 运维操作；leader持锁检查当前准备操作拥有执行权、其他调度/升级操作和删除意图，再唤醒其冻结的休眠池。先持久化候选及唤醒意图，丢失响应重试仅观察同一身份，不扩大范围。已完成升级步骤不会重做。
- 准备操作通过既有 `/admin/runtime-scheduling` 查询，携带精确runtime_type、phase及error_message。唤醒完成并获得原生注册证明后准备操作结束，再使用原有升级路径；Hermes/DSH使用逐池checkpoint，OpenClaw保留preflight/迁移/回滚要求。OpenCode现有安全升级拒绝保持有效，不把通用滚动替换当作原生数据安全升级。
- 镜像、slot worker image/ref/digest沿用现有RolloutImage同步逻辑。更新后的默认镜像/启动配置不得由外部脚本提前写入；后续发布工具只能提交CM接口并观察终态，失败必须停止。
- 零副本是生命周期状态，升级可以唤醒有证明的池；升级终态前自动缩容受既有admission阻挡，终态后自动休眠重新取实际新模板快照。用户实例不因无任务而在升级中被主动启动。
- 缩容中断恢复仅在同operation ID、Deployment UID、目标副本、源Pod集合消失、保留Pod集合、模板/PVC及实际owner证明一致时完成已经发生的动作；无法证明时保留needs_attention。禁止超时清记录、伪造终止证明或无条件释放全局保护。

## 准备到升级的接续

准备完成后以同一操作ID保留15分钟预约，UI与CLI把`preparation_id`传入预检及升级请求。持久化提交与预约消费使用同一SQL admission事务，完整池范围和删除意图在事务内再次核对。调度、容量维护、回收及自动休眠不得绕过预约。未使用预约可安全取消；原生证明失败的`needs_attention`不能被取消清除。

UI按账户在sessionStorage保存POST提交意图，收到确定结果或人工核对历史前禁止重提；CLI状态文件具有同样的中断保护，准备ID不能覆盖后续未确定阶段。原生证明失败单独保留受保护ID。历史候选不以客户端时间作硬身份条件，已知ID保持精确匹配且必须显式选择。SQL提交可能已发生的异常返回500，不能被当成可直接重试的409。

## 默认镜像提交

只有已完成、经过原生验证的业务rollout可成为默认镜像；待执行/失败、预检、lab与单实例恢复不改变默认值。新实例镜像卡和后端镜像查询使用一致的已提交镜像。CM重启只接纳有完整冻结UID/原镜像证明，且原生调度已停用或全部绑定均有已完成升级隔离授权的历史源池；不能从任意当前Pod推断默认版本，也不能重新创建已经退役的旧规范源池。历史最新成功记录若使用tag，则该类型保留原有显式配置，不采用更旧digest或历史源池覆盖；未来DSH升级入口拒绝非不可变digest，OpenClaw/Hermes沿用原有解析锁定路径。

## 交付与验收

测试/二进制/镜像构建只在10.130.81.54执行；本地仅源码、文档、静态检查与传输。不修改业务Runtime Deployments、镜像、实例或历史journal；测试使用独立数据库和fake Kubernetes，必要的真实Kubernetes验证使用隔离namespace。

验收覆盖：全部休眠、混合运行/休眠、无证明/漂移/换PVC拒绝、唤醒响应丢失与leader重启、升级失败/注册未就绪不能完成、升级后新休眠快照可唤醒、同类并发升级/调度拒绝、缩容前后中断收敛及未知外部写入不放行。更新AGENTS及正式发布工具，确保以后使用CM升级。
