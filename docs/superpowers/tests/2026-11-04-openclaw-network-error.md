# OpenClaw Network error 与过期 access token 排查

日期：2026-11-04。只读排查测试节点 `10.130.81.54` 的 `clawmanager-system`；未重启、停止实例，未发送模型请求。下文时间均为北京时间。

## 已确认的鉴权问题与正常拦截记录

### 通知 WebSocket 使用过期 token 重连

CM 当前 Pod 的访问日志中，`GET /api/v1/ws` 持续返回 401。只在节点内存中解码请求凭据，提取签发时间、到期时间、类型和请求时间，不输出或保存 token 本身。

截至 19:47 的日志样本包含两组已过期的 access token，其中一组 18:27:24 签发、19:27:24 到期，仍在 19:41—19:47 被用于重连；另一组更早到期。日志来自多个连接，不能将全部样本都归给当前用户浏览器。

`frontend/src/hooks/useWebSocket.ts` 在渲染时读取 localStorage 中的 token，再由回调捕获。连接关闭后每 3 秒重连，直接构造 WebSocket，没有 HTTP 的 401 刷新处理，也没有在每次重连前检查有效期。`services/api.ts` 的 Axios 刷新拦截器不会处理 WebSocket 握手，因此即使 HTTP 请求能刷新，通知连接仍可能继续使用旧凭据。

这证明当前版本存在通知鉴权的恢复缺口；尚不能据此断言用户截图内的聊天错误就是同一个问题，也没有足够证据确定它是某次历史修复的回归。

### 图像生成外部请求被出站策略正常拒绝

19:37:51，OpenClaw `slot-0` 的 `[image-generation]` 模块记录固定错误：

```text
fetch failed | Request was cancelled. | 0 |
Proxy response (403) !== 200 when HTTP Tunneling | UND_ERR_ABORTED
```

同一秒，实例 154（`lite-openclaw-129`）的审计事件 `egress.llm.blocked` 明确记录：连接 `api.openai.com:443` 因 `llm provider host blocked` 被拒绝。因此该条错误属于图像生成走到外部模型地址，不能解释为浏览器登录 token 过期，也不能通过放开出站限制解决。

只读取生成配置中的模型元数据，确认文本供应商 auto/icompify 都指向 CM 内部 Gateway，默认文本模型和 `imageModel.primary` 都是 `auto/auto`。此次外部请求被拒绝符合 CM 禁止直连外部模型的安全策略，属于正常行为，不是 CM 网络或鉴权缺陷，也不列为发布阻塞项。保留该记录仅用于解释对应工具请求的失败；不因此修改出网策略或新增路由。

## 后续澄清：空白发生在嵌入的 OpenClaw 页面

用户确认 CM 外层页面仍正常，是嵌入的 OpenClaw 页面空白；点击嵌入框刷新后恢复。因此不能用 CM 通知 `/api/v1/ws` 的 401 直接解释这次空白，也不能把图像生成模块的 403 当作页面空白的直接原因。

检查 `useInstanceDesktopAccess.ts` 与 `InstanceServiceFrame.tsx` 发现恢复缺口：

- 嵌入访问凭据与 CM 登录 access token 是两套凭据。嵌入访问已有提前 5 分钟续期逻辑，因此不能笼统声称它没有自动续期。
- `handleFrameError` 仅在尚未建立会话时请求新凭据并重载；建立过会话后直接结束处理。
- `handleFrameLoad` 即便识别到匹配的访问鉴权/代理错误，也只在尚未建立会话时重载；空白 body 则可能被标记为已建立。它不是应用成功渲染的可靠证明。
- OpenClaw 的 iframe 存在时，外层直接渲染 iframe，没有像 Browser Worker 面板一样叠加明确的连接失败提示。iframe 内部的脚本错误或 WebSocket 失败也不保证触发 iframe 的 `onError`，仅补该回调不足以覆盖所有情形。

刷新恢复与这些缺口相符，但仍缺少空白发生瞬间的浏览器网络/脚本错误证据，不能在凭据失效、CM 更新中断、OpenClaw 自身渲染异常之间作出唯一归因。19:41:09 的 CM 更新是已知的连接中断事件，只能作为候选触发因素。

后续应验证已建立的 OpenClaw 页面在断连后能恢复，采用可靠的连接/页面健康信号、有限重试与可见的失败提示，避免因误判而持续刷新或丢失未发送输入。此轮没有修改上述逻辑，也没有对用户实例执行停止或重启。

用户随后授权修复，嵌入页恢复缺口已修正并部署，验收见[嵌入页恢复修复记录](2026-11-04-openclaw-frame-recovery.md)。上述未修改的描述属于排查阶段快照；通知 WebSocket 仍为独立待修项。用户再次明确，`api.openai.com` 被拦截是正常策略行为，不算问题，已据此修正本记录的分类。
