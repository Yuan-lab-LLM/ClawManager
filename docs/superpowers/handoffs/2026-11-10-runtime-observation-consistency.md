# Runtime 环境与数据库一致性：部署验收

本轮已完成实现、真实 MySQL 回归、镜像发布和现场对账。源码在 `preview`；没有创建 PR。

## 行为与边界

- `runtime_pods.observation_json/observation_at` 持久化经过筛选的现场事实，按当前 Pod UID 和递增观察时间更新。旧扫描不能覆盖新扫描，更换 UID 时清除旧观察。分配绑定和观察事实分别记录，不从弱上报中编造租约。
- 既有选主巡检器把 Runtime、数据库绑定、原生 assignment 预留和隔离状态一并对账，接受观察保存后才执行后续操作。未知、冲突、无绑定残留不会被显示为空闲或授予迁移、驱逐权限。
- 有充分停止证据时，旧绑定与槽位计数通过同一条件事务释放；身份、实例状态、代数、Gateway ID 或端口变化时拒绝释放。
- 自动回收在发布计划及最终修改副本数之前，锁定源 Pod 行再次检查最新完整的空闲观察。新的预留、占用、未知或过期状态都能阻止回收。
- 兼容现场旧镜像只在 assignment 中返回 Pod UID 的报文：仅当其匹配已核实的当前 Pod 时保留报告身份；不补造 worker epoch、空闲证明或清理权限。非空外来顶层 UID、缺失或外来嵌套 UID 仍被拒绝。
- 旧镜像不足以确认退出的槽位保留为“未知”，包括已停止 assignment 的历史身份。它们是待确认的槽位记录，不代表正在运行的实例数量。不会通过删除未知环境来制造数据库一致。
- 备份契约已加入新字段；恢复时清空旧 Pod UID 和观察结果，防止把原环境的现场证明带到新环境。
