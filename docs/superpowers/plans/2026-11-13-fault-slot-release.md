# 故障恢复后的 Runtime 槽位释放

故障恢复的节点助手已经持久化独立停止回执，但 CM 解绑后没有将它交给重启后的 worker，后者仍持有旧 assignment/stop intent。此次补齐实际槽位释放，不修改工作区数据，也不将故障回执冒充优雅停止回执。

1. Runtime 增加独立的故障停止核验与释放接口。核对旧 Pod、slot、用户、实例、代次、assignment digest/epoch；验证共享管理目录中的节点助手回执，要求当前 worker 已与旧执行分离且没有本地执行、租约或网络资源。先持久化停止结果并保持隔离，再由 CM 确认释放。历史回执不得更改新的 writer。
2. CM 故障 journal 记录槽位核验与释放检查点。仍存在的原 Pod 必须完成此协议才提交解绑；消失的原 Pod 明确记录源已退役。对历史 completed/released journal 有界重试，仅清理旧槽位，不回放实例生命周期操作，不解除调度暂停。
3. 在 81.54 运行先失败后通过的协议测试：错误身份/回执、活跃执行、丢失响应、重启、保存失败、新 writer、旧版本拒绝、历史 journal 重试和实际 free 核验。
4. 只在 81.54 构建二进制及镜像；CM 应用使用现有部署流程，Runtime 镜像使用 CM 原生滚动升级 CLI。保留旧镜像和发布状态文件，完成实际槽位重用验收后再报告完成。

联调补充：Runtime 的 capsule 管理父目录为 UID 10001 / 0711；CM 锁助手同时接受旧 0700 和这个精确布局，operations 子目录仍须 0700，锁文件仍须 0600。控制器携带升级 claim 时，仅兼容检查 RPC 使用短工作片并继续同一持久操作；Kubelet 重启退避不得长时间占住其他类型实例的创建和回收。迁移、回滚及非控制器请求保留原超时，原生停止证明、结果持久化和释放顺序不变。
