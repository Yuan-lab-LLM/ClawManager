# Lite 空闲 Pod 弹性缩容与人工启动恢复

用户已确认实施。只针对 Lite；不添加请求唤醒。沿用实例自动停止总开关、按天的业务空闲策略及现有测试构建的 1 分钟扫描 / 5 分钟空闲设置。

## 设计

- 实例停止并释放槽位后，Pod 连续空闲 60 秒才参与自动缩容。检查平台绑定、未发布的槽位预占、Agent 最新空槽报告及 Kubernetes 原生分配状态。
- 自动处理所有普通服务池，包括正式启用的升级目标和自定义池。只移除空 Pod，不迁移业务实例；允许最后一个 Pod 缩至 0。现有手动缩容至少保留一个副本的约束不变。
- 复用持久化 `scale_in` 操作日志、调度暂停、Pod UID 校验、保留 Pod 删除保护、Deployment CAS、控制器收敛检查和中断恢复。升级、迁移、未确认停止及新启动需求存在时保守推迟自动缩容。
- 已完成的自动缩容日志保存池 UID、模板和来源，作为从 0 恢复的依据。管理员手动关闭的池、停用旧池、模板或 UID 已变的池不可通过该路径自动恢复。
- 用户点击现有启动按钮后，优先复用可用容量；没有合适容量时，按实例原池 / 已提交升级策略恢复一个匹配池，再等待真实 Pod 注册并执行原有分配校验。恢复容量不能替代实例身份、存储、镜像及升级策略检查。
- 不删除 Deployment、PVC 或工作空间，不通过心跳超时推断停止成功。资源不足沿用启动等待和失败提示，可由用户重试。

## 实施与验证

1. 增加从 0 缩容 / 恢复、模板变化拒绝恢复、手动零副本不恢复等失败测试；全部测试只在 10.130.81.54 运行。
2. 扩展内部缩容计划与 Kubernetes 校验以支持空 Pod 自动缩容至 0，复用现有持久化执行器。
3. 将空闲观察接入现有 leader 调度循环；使用持久化操作日志实现安全恢复，重启后重新计时。
4. 接入人工启动容量恢复，覆盖四种 runtime 和 OpenClaw 已升级池。
5. 在测试节点运行针对性测试、构建镜像并更新主测试命名空间；实测空 Pod 缩至 0、四类实例人工启动、工作空间持久化、再次空闲回收及副本 / 数据一致性。
6. 记录测试证据、限制与生产恢复方式。禁止本地构建、运行测试或启动任何集群。
