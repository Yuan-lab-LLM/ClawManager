## 当前实现边界

用户已明确：**CM 不允许 Agent 直连外部模型，模型调用统一经过 AI Gateway。** 本功能复用这个既有平台约束及 Gateway 的可靠活动登记；不新增“直连外部模型实例”的正常豁免类型，也不要求每个实例提供额外的“全部模型覆盖证明”。

此前因只看到保留 provider 配置和普通出网分支，漏查后端 egresspolicy 的模型供应商拦截而提出的“覆盖证明不足，全部阻断回收”判断有误。相关运行时资格字段、数据库提交门槛、状态表和界面阻断已移除；平台已登记任务、活跃请求、持久存储和优雅清理的保护继续保留。若发现真正的直连绕过，应作为现有平台安全约束的实现缺陷单独修复，不能把它变成正常产品能力或本功能的新前提。

默认策略版本/来源状态仅用于展示，不额外改变空闲判定。空闲仍取连续 Gateway 活动窗口，默认1天、最小1天；人工启动，无请求唤醒。

2026-11-03 用户明确要求四类 Lite 统一按模型调用判定。已移除 CM 对原生任务静默结果的资格判断和 Runtime 的类型专用任务钩子；公共停止接口可用性、实例身份与代次仍在提交停止前核对，不再要求 OpenClaw 固定版本或其他 Runtime 提供原生执行证明。四类共用 supervisor 命令入场保护、graceful_only 停止和清理回执；持续低频/无模型业务使用管理员保持运行。原生四类测试结果与镜像见统一判定的补充报告，上一轮仅 OpenClaw 的结论属于历史记录。
