# 安全防护平台指南

**安全防护**是 ClawManager 管理端独立的工作区，不属于用户侧资源管理。它把 Runtime 防御、主机与容器保护、组件可信、身份与策略、协作治理、应急响应和安全事件汇总到同一操作视图。

![ClawManager 安全防护总览](./main/security-protection-current.png)

## 总览指标

页面顶部按实时告警数据展示：

- 今日 00:00 起的防御命中数；
- 最近 24 小时高危事件数；
- 最近 24 小时动作包含 block/deny 的拦截事件数；
- 最近 24 小时涉及的不同智能体实例数。

告警会自动刷新。页面下方聚合最近 10 条跨产品安全事件，显示时间、来源、防护场景、事件证据、目标和严重级别，并可进入完整事件流。

## 管理员操作

- **Pod 实时 Aegis 配置**：打开受管 Runtime 的实时安全配置与下发流程。
- **导出报告**：把当前已加载告警导出为 JSON Lines；没有告警数据时不可用。
- **应急熔断**：要求填写原因并二次确认，然后向目标 Runtime 下发应急状态。熔断启用后，页面会显示启用人、时间与原因，并提供受控解除入口。

这些操作会影响平台运行。修改实时配置或启用熔断前，应先确认目标范围和影响。

## KSecure 纵深防御模型

总览当前以 **7 大风险面、15 个防护场景、4 个防护层级**呈现产品模型。管理员可以在层级视图和环形视图之间切换，并从风险面卡片进入具体场景。

### 运行时层

- **智能体运行时安全**：输入面检测、状态与记忆保护、危险决策/工具调用控制、输出脱敏、资产防篡改和人因审批。

### 主机层

- **环境隔离与安全增强**：宿主加固，以及容器隔离与防逃逸。

### 审计层

- **数据与组件可信**：Skill Scanner 报告与配置，以及受控的私网出站例外。

### 控制层

- **统一身份与权限**：出站治理和可信目的地控制。
- **安全策略与模板**：统一策略治理。
- **监管与运营治理**：应急熔断与全链路审计。
- **协同接入与通信**：Team 协作治理与 AI Gateway 配额限制。

每张卡片都是相应场景页面的入口。实际可用的执行与下发能力取决于已部署的安全服务和 Runtime Agent 配置；页面可见不等于所有后端控制都已生效。

## 建议操作流程

1. 先看四项实时指标和最近事件。
2. 定位受影响实例、规则、来源与防护场景。
3. 进入对应风险面查看配置或证据。
4. 优先采用影响范围最小的策略或 Runtime 调整。
5. 只有在确需中断且已确认范围时才使用应急熔断。
6. 核对后续事件和 Runtime 状态，按需导出报告留证。

## 功能边界

- **资源管理**负责通道、技能、定时任务、资源包与注入记录，不是安全看板。
- **Skill Scanner**只是安全防护“数据与组件可信”中的一个场景。用户在 Skill Hub 上传版本、查看扫描状态和报告；管理员在安全防护中检查 Scanner 健康、失败任务、模型/Meta LLM 配置、Quick/Deep 策略及相关安全事件。扫描完成是证据，不等于自动允许发布或安装。
- 安全防护不能替代 Kubernetes 加固、网络策略、凭据管理、备份和组织自己的事件响应制度。
