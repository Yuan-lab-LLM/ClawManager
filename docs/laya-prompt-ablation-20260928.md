## 结论

复现了用户报告的“帮我写一个 Python 排序函数”被当前 v2 分为 3 档的问题。缩短说明后变为 2 档，说明提示词会影响结果；但整批测试仍有明显错误，不能认为只改提示词就解决了能力分档问题。

本轮落地了管理端概率诊断、返回值一致性校验和可复现评测工具。**没有替换正式 v2 提示词，没有启用 Laya Auto，没有更新 ClawManager 镜像或 K8s。**

## 已完成的代码改动

- 后端保留 `confidence` 兼容字段，增加 `confidence_kind = normalized_entropy` 和四档 `probabilities`；审计决策也记录指标类型。
- 管理端显示四档概率、最高选项概率、前两名差距；将旧“置信度”改为“分布集中度（非正确概率）”。旧后端未返回分布时不伪造数值。
- 校验概率范围、总和及所选档位与最高概率是否一致，容忍四位小数舍入；无效响应走已有错误处理。没有加入未经校准的概率回退阈值。
- 新增五配置离线评测、20 条新合成题、真实规则结果合并脚本和回归测试。Python 调用脚本同步修正指标名称。

验证：后端 aigateway / handlers 测试及 server 编译通过；Python 客户端 11 项、评测脚本 7 项、前端设置页 9 项测试通过；TypeScript、定向 ESLint 和前端构建通过。构建有非阻断性的 chunk 体积警告。

## 后续建议

1. 先使用新增概率诊断观察结果，继续保留规则作为正式默认；B 仅作为下一轮验证候选，不直接发布替换。
2. 人工复核一批独立中文业务样本，重点覆盖简单任务、常规编程、续问、翻译材料里的复杂指令；明确 2/3 档的边界。
3. 在独立样本上对比 B、v2 和规则，同时看低估、各档结果和分类开销；通过后再决定是否切换提示词或采用混合分类。
4. 概率阈值需要单独校准，不能凭本题的 52.8%、81.02% 或 5.66 个百分点拍定。
