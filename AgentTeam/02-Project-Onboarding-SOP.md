# Project Onboarding SOP

## 1. 目标
当总司令第一次接手一个新项目时，必须先完成“项目适配”。

项目适配的目的不是写代码，而是让总司令建立一个可用于后续分发任务的项目模型。

## 2. 何时触发
必须触发的场景：
- 第一次进入一个新项目
- 切换到一个完全不同的代码库
- 继承别人做了一半的项目，但当前上下文不完整
- 项目发生重大结构变化，原有上下文已经失效

## 3. 接管结果必须产出什么
项目接管完成后，总司令至少应该拥有以下 6 个东西：

### A. 项目画像
包括：
- 这是个什么项目
- 主要目标是什么
- 当前阶段是什么
- 谁是用户 / 维护者 / 主要利益相关人

### B. 仓库地图
包括：
- 主要目录结构
- 哪些区域是核心逻辑
- 哪些区域是文档、脚本、配置、生成物
- 哪些区域是冻结区或不建议改动区

### C. 规则地图
包括：
- AGENTS / README / CONTRIBUTING / docs 中的规则
- 代码风格约束
- 验证命令
- 禁改区域
- 安全与合规约束

### D. 当前上下文
包括：
- 当前正在做什么
- 最近已完成什么
- 当前未完成项是什么
- 目前最大的风险和阻塞是什么

### E. Agent 路由图
包括：
- 什么类型的任务适合派给什么 Agent
- 哪些部分适合并行
- 哪些部分必须串行
- 哪些区域需要总司令亲自盯住

### F. 初始行动建议
包括：
- 下一步最合理的任务是什么
- 先做什么，不做什么
- 需要补哪些缺失文档或记录

## 4. 项目接管步骤
### 步骤 1：读规则
优先读：
- 根级说明文件
- AGENTS / CLAUDE / README / docs
- 项目级 runbook / spec / plan / tasks
- 最近进度记录或 handoff 记录

目标：先搞清楚“什么不能做”和“什么必须先做”。

### 步骤 2：画仓库地图
识别：
- 核心代码目录
- 测试目录
- 文档目录
- 脚本目录
- 构建 / 发布目录
- 冻结目录
- 生成物目录

目标：知道后面任务应当分发到哪里。

### 步骤 3：找验证入口
识别：
- 如何运行
- 如何测试
- 如何检查语法
- 如何做最小 smoke
- 哪些命令能证明“工作完成”

目标：后面任何“完成”都要有证据可追。

### 步骤 4：读近期上下文
识别：
- 最近做了什么
- 哪些 feature 已完成
- 哪些 bug 正在处理中
- 当前最接近的后续任务是什么

目标：避免重复劳动，也避免被过期上下文带偏。

### 步骤 5：建立 Agent 路由图
把任务分成：
- 规划类
- 实现类
- 验证类
- 文档类
- 集成/裁决类

然后决定：
- 哪类任务派哪种 Agent
- 哪些区域允许并行
- 哪些区域必须总司令保留最终决定权

### 步骤 6：输出接管结论
总司令需要形成一份简明结论，至少回答：
- 这个项目现在处于什么状态
- 当前最值得做的下一步是什么
- 接下来应该用什么编队来做
- 当前最大风险是什么

## 5. 接管完成前，不能做什么
在项目接管完成前，不应：
- 大规模派工
- 让多个实现 Agent 并行改动
- 宣称自己已经理解项目
- 给出高确定性判断
- 直接复用上一项目的派工习惯

## 6. 项目适配后的日常更新
项目适配不是一次性死文件。

后续由总司令持续维护：
- 新增约束
- 新增验证方法
- 目录变化
- 当前主线目标
- 近期风险

如果项目发生大变化，应重新跑一次完整接管。

## 7. 推荐输出格式
建议总司令在每个项目里沉淀一份“项目接管摘要”，包含：
- 项目简介
- 目录地图
- 关键规则
- 验证命令
- 当前目标
- Agent 路由建议
- 风险与注意事项

这份摘要不必使用固定文件名，但必须存在一个可持续更新的落点。
