本次 Skill Hub 的八表恢复、对象校验、统一恢复校验入口和 worker 排空已经有实现，MySQL/MinIO 专项也已有通过记录。接下来请按下面两阶段推进。

**一、现在先完成的工作**
1. **确认写入路径归属。**  
   将已盘点的十组 writer 标清负责人：你负责 Skill Hub 自身的 service/worker；B 负责的 workspace/runtime、D 负责的安全扫描，由对应负责人改造。说明你负责的路径准备在哪些事务、回调和任务阶段接入公共停写保护。
2. **确认接入依赖。**  
   在现有交接文档中列清需要公共层提供的接口和输入，包括 Runner 请求、用户/实例映射、权限证明、对象上传回执和 workspace 恢复证明。每项注明提供方、接入位置和当前阻塞点，已有内容无需重复整理。
3. **提交策略评审并处理反馈。**  
   将八表恢复规则、任务状态处理、对象和 metadata 策略交给 A/B/D 评审。你负责解释和修正本模块，审核签收由对应负责人完成。
这个阶段可以交付为“Skill Hub 模块已实现，待公共能力接入”。继续保持 `runtime_ready=false`，不要把本地 worker 排空当作全局停写成功。
**二、B/C 等公共能力到位后，完成以下接线**
1. **接入本模块写入保护。**  
   将你负责的 service/worker 接入公共 gate、lease 和事务提交检查。停止接单后要等待在途任务退出；超时、归还失败或权限失效时，不能报告停写成功。
2. **接入正式 Runner。**  
   让 Runner 调用已有的归一化、SQL 恢复和统一恢复校验入口，使用公共层提供的可信输入、隔离目标连接及权限证明。
3. **接通对象备份和恢复。**  
   使用公共层的加密候选存储、恢复上传和目标版本回执，核对数据库中的对象映射、完整对象清单、目标内容及 metadata。
4. **接入 workspace 证明。**  
   使用 B 提供的真实恢复证明，覆盖实例绑定、工作区路径和未打包 blob，不能仅凭 evidence ID 格式正确就判定成功。
5. **输出正式检查结果。**  
   按 D 提供的协议输出统计、检查项、警告和证据，保留所有会影响验收资格的问题，包括 metadata 省略。
6. **完成 Skill Hub 集成验证。**  
   验证八表、对象、workspace 联合恢复，并覆盖取消、迟到回调、权限过期、fence 失效和多副本停写等场景。修复属于 Skill Hub 的问题，公共层问题交对应负责人处理。
公共 gate/lease/fence、Runner 框架、权限基础设施、加密存储、workspace 证明机制和正式检查协议，**不要求你重新实现**；你负责接口到位后的 Skill Hub 侧接入与验证。
不必等 B/C 全部完成，哪个接口先稳定就先接哪个。沿用已有有效测试结果，对新增接线补测试；不要自行安装依赖，测试、构建产物结束后清理。
